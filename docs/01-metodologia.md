# 01. Metodología de documentación

## Cómo elaborar este apartado

1. Describe el proyecto y delimita qué se va a documentar.
2. Identifica requisitos antes de dibujar diagramas o escribir pruebas.
3. Asigna identificadores únicos y estables.
4. Relaciona requisitos, casos de uso y pruebas.
5. Distingue siempre los ejemplos de los resultados reales.
6. Actualiza la documentación cuando cambie el proyecto.

## Plantilla vacía

- **Método de trabajo:** [Cómo se organizará el trabajo]
- **Herramientas:** [Editor, repositorio, herramientas de diagramas y testing]
- **Convención de identificadores:** [RF-001, RNF-001, CU-001, CP-001...]
- **Control de cambios:** [Cómo se registrarán los cambios]
- **Revisión:** [Quién revisa y con qué criterios]

## Ejemplo ficticio

- **Método de trabajo:** documentación incremental.
- **Herramientas:** Markdown, GitHub y diagramas Mermaid.
- **Identificadores:** RF para requisitos funcionales, RNF para no funcionales, CU para casos de uso y CP para casos de prueba.
- **Control de cambios:** registrar los cambios relevantes mediante Git.
- **Revisión:** comprobar consistencia, enlaces y trazabilidad antes de cada entrega.

## Lista de comprobación

- [ ] El método de trabajo está explicado.
- [ ] Los identificadores son consistentes.
- [ ] Se diferencia la documentación prevista de los resultados reales.
